# HY4 Flash tuning on November 23, 2026

One DGX Spark ran the pinned AngelSlim Spark-4Bit-Fast GGUF over the loopback API. The single-user comparisons held the 196,608-token configured context, F16 KV, Engram placement, sampling settings and 400-token thinking-on prose workload fixed. Each startup was followed by an unscored warmup and six measured requests.

## Startup

The Direct I/O arm changed only `--load-mode` from `mmap` to `dio`. The lazy CPU Engram mapping stayed enabled. Launch-to-health was measured in whole seconds. The decode results follow a warmup request, and the filesystem page cache was left in its normal state.

| Profile | Launch to health | Median decode | Median TTFT |
| --- | ---: | ---: | ---: |
| [mmap control A](../results/tuning-20261123/mmap-control-a.json) | 175 s | 29.60 tok/s | 135 ms |
| [Direct I/O](../results/tuning-20261123/direct-io.json) | 12 s | 27.94 tok/s | 135 ms |
| [mmap control B](../results/tuning-20261123/mmap-control-b.json) | 161 s | 28.10 tok/s | 134 ms |

Direct I/O is available via `HY4_LOAD_MODE=dio`. mmap remains the default because this experiment measured a startup gain and did not establish an improved decode rate. The scored Direct I/O launcher passed `--load-mode dio` and produced no buffered-fallback warning. An earlier trial labeled Direct I/O actually used mmap, so it was excluded and rerun. The larger microbatch test was deferred to leave time for the selected profile’s validation. ## MTP ×2 qualification

A fresh six-request replay reached **30.96 tok/s median**, **32.00 tok/s peak** and **135 ms median TTFT**. Standard chat, separate reasoning, exact Traditional Chinese copying and the tool-call round trip passed. Unique 32K and 128K prompts both returned the exact retrieval code with zero cached input tokens. Recorded client prefill was **695.1 tok/s** at **47.13 s TTFT** and **594.1 tok/s** at **220.61 s TTFT**. Peak sampled GPU-process allocation was **92.7 GiB** with a minimum **22.3 GiB** host `MemAvailable`. This run selected greedy MTP ×2 as the one-slot baseline for the next sweep. ## Probabilistic MTP ×2

The later sweep used the same loopback client, Fast GGUF, F16 KV, context, memory mapping, and thinking-on prose workload. Each fresh server ran a 32-token warmup followed by six 400-token requests at target temperature 0.7, top-k 20 and top-p 1. Each candidate changed one setting.

| Profile | Median decode | Fastest request | Median TTFT | Draft tokens accepted |
| --- | ---: | ---: | ---: | ---: |
| [Greedy MTP ×2, control A](../results/tuning-20261123-probabilistic/control-a.json) | 30.75 tok/s | 31.97 tok/s | 135 ms | 52.03% |
| [Probabilistic MTP ×2](../results/tuning-20261123-probabilistic/draft-prob.json) | **32.49 tok/s** | **34.40 tok/s** | 135 ms | 56.98% |
| [Greedy MTP ×2, control B](../results/tuning-20261123-probabilistic/control-b.json) | 30.55 tok/s | 32.34 tok/s | 134 ms | 52.03% |

| [Greedy MTP ×2, control C](../results/tuning-20261123-probabilistic/control-c.json) | 30.26 tok/s | 31.65 tok/s | 134 ms | 51.92% |

| [Greedy MTP ×2, control D](../results/tuning-20261123-probabilistic/control-d.json) | 30.56 tok/s | 31.57 tok/s | 133 ms | 50.99% |
| **[Probabilistic MTP ×2, fresh replay](../results/tuning-20261123-probabilistic/qualification.json)** | **32.76 tok/s** | **34.72 tok/s** | **134 ms** | **59.43%** |

Probabilistic MTP ×2 improved median decode by **5.6–6.3%** against its two adjacent controls while adding about 1 ms or less to median TTFT. The drafter samples from its candidates, and the target can accept through rejection sampling using both probability distributions. The target settings stay fixed. MTP ×1 and whole graph capture fell short of the sweep's improvement and repeatability criteria. [Pinned sampler implementation](https://github.com/ggml-org/llama.cpp/blob/2cbca389f515df455412dafa07e2b1359cc72a6d/common/sampling.cpp#L734)

All six replay requests exceeded **32 tok/s**. The replay passed chat, separate reasoning, exact Traditional Chinese copying, a tool-call round trip, and exact retrieval on fresh 32K and 128K prompts. The launcher now defaults to probabilistic drafting for one slot with MTP enabled. The fastest five-user preset uses MTP off.
